# 30 / 60 / 90-day horizon

## First 30 days: measured truth

### Outcomes

- stale issues and authority docs reconciled;
- benchmark metric, transport and corpus ADRs accepted;
- failed cost and layered metrics implemented;
- journal/resume and run manifest complete;
- synthetic candidates reviewed and real fixtures sourced;
- offline full-corpus rehearsal green;
- paid pilot and full run complete;
- v0.1 report and release published;
- first release-gate baseline promoted.

### Do not expand scope

No OCR, invoice.v2, new providers or public SaaS work unless the benchmark exposes a direct blocker.

## Days 31-60: repeatability and operations

- representative paid canary subset;
- workflow-dispatched canary on provider/prompt/schema/client changes;
- gateway integration evidence;
- request/run IDs and structured redacted logs;
- Docker/resource hardening;
- branch required checks include Docker/release proof;
- canonical project state and drift checks;
- shared agent-floor provenance resolved;
- legacy hook/normalizer cleanup.

## Days 61-90: choose one evidence-backed expansion

Select exactly one:

1. **invoice.v2**, if real v1 exclusions/failures justify it;
2. **third schema**, only with a real internal/client caller and fixtures;
3. **vertical workflow**, such as invoice review/export or job-market intelligence;
4. **release-gate productisation**, if repeated model/gateway comparisons are the strongest pull.

Do not choose by novelty. Use baseline failure clusters, actual internal use and willingness to maintain the corpus.
